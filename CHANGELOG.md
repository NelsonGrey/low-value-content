# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- Added `docs/product/product-copy.md`: shared garment/care/made-to-order blocks, one-line descriptions for all twenty issues, and a draft shipping, returns and support policy that needs owner decisions.
- Wave 2: ten new issues (Nos. 11-20) chosen from the sayings review, with proof artwork on the shared House frame (`design/prototypes/11-*.svg` to `20-*.svg`, generated by `scripts/build-wave2.py`) and `docs/product/wave-2.md`.
- Blank and print specification (`docs/product/blank-and-print-spec.md`): Comfort Colors 1717 recommended, margin reasoning, the quality/printability balance, and a first-week verification checklist. `scripts/upscale-plates.py` upscales the ornate plates (Nos. 07-10) to a 3600 x 4500 print candidate.
- Lineage: the eleven sovereigns no longer all carry "I". Sole bearers have no numeral and every reign has an epithet (Moth the Pious, Algorithm the Terrible, Content the Wanting, Prompt the Confident, and so on); the second Web is Web II the Chastened. Reign ids in the manifest lost their `-i` suffix. The lineage page explains the naming rule and shows "Reign 01" to "Reign 11".
- Added `docs/product/sayings-review.md`: a Realm-aligned ranking of the 100 sayings with a twenty-line Wave 2 shortlist by House, five commemoration lines, and a cut list.
- Content consistency pass. Product pages and cards are shopper-facing (production fields, the repeated Launch Constitution block and the front-art spec section are gone; lore sits in a collapsed archive note). The Royal House is the visible brand on every page title and on the coming-soon page, which now uses the House palette. Collection naming is "the founding collection". Garments are limited to Ivory, Oxblood, Navy and Black. Nos. 01–06 carry the shared House frame and imprint, are rebuilt in the House inks, and are rendered by `scripts/render-front-art.py`.
- Nos. 07–10 now use the ornate full-colour artwork plates across the manifest, storefront, shop proof sheet, and production docs; the retired line art is kept as `legacyArtwork`. Product pages label the plates "not yet print-ready".
- Storefront scripts and styles are external files, so the dev and staging Content-Security-Policy no longer blocks the menu, calendar highlight, or page styles. `scripts/check-site.py` now fails on inline scripts, styles, and `style=` attributes in the built site.
- Product price on the storefront is read from the manifest instead of being hard-coded.

### Fixed
- Cancelling Stripe Checkout returns to `/shop` instead of the nonexistent `/shirts#validate`.
- Shop copy now matches the collection counts (4 Public Notices, 4 Court & Orders, 2 Royal Commemorations).

### Added
- Astro storefront for the Royal House of Engagement (Realm, Lineage, Royal Calendar, ten product pages) generated from the master apparel manifest.
- Repository standards: CI (site checks, gitleaks secret scan, advisory promotion guard, Pipeline Summary), CLAUDE.md, expanded SECURITY policy, `.gitattributes`, `.gitleaks.toml`, grouped Dependabot, meta descriptions on legal pages, and a filled-in GitHub About section.
- Commerce backend (`functions/`): Stripe Checkout sessions, verified Stripe and Printify webhooks, idempotent Printify order submission held for manual approval, Firestore order ledger, public order-status endpoint, and scheduled reconciliation. Test-mode vertical slice on the Drop 001 "validate" shirt; checkout refuses placeholder Printify IDs.
- Branded coming-soon page for production, controlled by the `SHOW_COMING_SOON` environment variable.
- Keyless deploys via Workload Identity Federation (org policy forbids service-account keys).
- Google sign-in access gate on dev and staging with domain and exact-email allowlists (parity with vehicle-vitals).

### Removed
- Duplicated files at the repository root and in `design-prototypes/`, `mockups/`, `output/`, and two `qa-business-plan*` temp directories; the maintained copies live under `docs/`, `design/`, and `tools/`.

### Changed
- README, brand guide, concept catalog notes, `functions/README.md`, and CONTRIBUTING reflect the ten-design Royal House launch, the real commerce catalog state, and hosting-only CI deploys.
- The business plan builder adds an "Implementation Update" section (ten designs, Stripe and Firebase, Printify hold-for-approval, test-only commerce); the original plan text is unchanged and its QA renders are not regenerated.
- Dependabot now also covers the `website/` and `functions/` npm packages.

## [0.1.0] - 2026-10-13
